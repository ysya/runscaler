# Go 1.27.3 Security Release Implementation Plan

> **For agentic workers:** Execute inline with superpowers:executing-plans and use superpowers:verification-before-completion before publishing.

**Goal:** Upgrade the v0.9.5 maintenance line to Go 1.27.3 and publish v0.9.6 after tests and vulnerability checks pass.

**Architecture:** Keep the existing Go module, Docker build, and GitHub Actions release flow. Make CI reusable by the release workflow so publication waits for the same checks as pull requests.

**Tech Stack:** Go 1.27.3, Docker, GitHub Actions, govulncheck v1.9.0, GoReleaser.

**Spec:** User request in this chat: upgrade Go, Docker and CI, add vulnerability checks, test, and publish a new release.

## Global Constraints

- Start from v0.9.5; preserve unrelated, unreleased main changes.
- Use Go 1.27.3 for module, container builds, CI and releases.
- Do not modify application behavior or upgrade unrelated dependencies.
- Publish only after local checks and release workflow checks succeed.
- Preserve both runner and runscaler compatibility assets.

## Review Focus

- A cached or automatically downloaded toolchain must not silently replace Go 1.27.3.
- Linux and macOS must both run race tests and source vulnerability checks.
- Scheduled vulnerability checks must run without requiring a code change.
- Release publication must depend on the complete CI workflow.
- Verify downloaded release checksums and embedded Go version without executing foreign binaries.

### Task 1: Pin the toolchain

**Files:** `go.mod`, `Dockerfile`

- [x] Change the Go directive to `1.27.3` and builder to `golang:1.27.3-alpine`.
- [x] Disable automatic toolchain switching in Docker and workflow environments.
- [x] Verify the Docker tag and build metadata.

### Task 2: Gate releases on tests and vulnerability checks

**Files:** `.github/workflows/ci.yml`, `.github/workflows/release.yml`

- [x] Add Linux/macOS matrix race tests, vet, and pinned govulncheck source scanning.
- [x] Add weekly and manual CI triggers and a reusable workflow entry point.
- [x] Make release depend on the reusable CI workflow with read-only permissions for checks.
- [x] Validate workflow syntax using actionlint.

### Task 3: Verify and publish

- [x] Run full tests, race tests, vet, lint, and vulnerability checks with Go 1.27.3.
- [ ] Verify builds for all four supported OS/architecture combinations and Docker when available.
- [x] Obtain an independent review and resolve material findings.
- [ ] Commit with Conventional Commits, push the maintenance branch, and tag v0.9.6.
- [ ] Wait for release CI, verify all compatibility assets and checksums, and inspect embedded Go versions.
- [ ] Report the release URL and distinguish publication from deployment.
