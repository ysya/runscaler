設定ツール

config.toml を作成。

スケールセット、キャッシュ、ホストの設定を選びます。生成した TOML をコピーし、自分のホスト上で認証情報を追加して検証してください。

● 認証情報の入力・送信は不要編集をはじめる ↓
スケールセットActions キャッシュディスク監視プロセス設定

01 / ランナー

スケールセット

各スケールセットは GitHub 組織またはリポジトリに接続します。

02 / キャッシュ

内蔵 Actions キャッシュ

対応するランナーイメージ向けの任意のプライベートキャッシュ受信機能です。Docker スケールセットでは外部エンドポイントも使用できます。

標準のランナーイメージはキャッシュに対応していません。受信機能を有効にする前に、対応するイメージとプライベートアドレスを用意してください。導入ガイド ↗

03 / ストレージ

ディスク監視

空き容量が不足するとホスト全体をクリーンアップします。レベル 4 では旧形式のキャッシュボリュームを空にする場合があります。

04 / プロセス

グローバル設定

ログ、ヘルスチェック、同時実行数、診断はプロセス全体に適用されます。

TOML

ホスト上で仕上げる

ファイルを保存し、ホスト上で PAT を追加するか、GitHub App の秘密鍵を指定したパスに配置してから、runner validate を実行してください。ファイルの権限は 0600 に設定します。通常の保存先は Linux では /etc/runner/config.toml、macOS のユーザーサービスでは ~/.config/runner/config.toml です。

Docker または Tart の デプロイガイド ↗ に従ってください。
