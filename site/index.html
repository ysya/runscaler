THE IDEA

Capacity follows the queue.

Keep your own host and workflow. Runscaler handles the runner lifecycle between them.

01 / LISTEN

Wait for real work

Long-poll the GitHub scale-set API and start runners in response to assigned jobs.

02 / RUN

Choose the right host

Use Docker containers on a Docker host or Tart virtual machines for macOS jobs.

03 / RECOVER

Leave a clean slate

Each runner handles one job. Runscaler removes it afterward and reconciles resources after a restart.

01

Install

Start Docker, then install the runner binary on Linux.

curl -fsSL https://raw.githubusercontent.com/ysya/runscaler/main/install.sh | sudo sh
02

Save and add credentials

Paste the TOML into the file, fill the PAT locally or place the App key file, then protect the config.

sudo install -d -m 0700 /etc/runner
sudoedit /etc/runner/config.toml
sudo chmod 0600 /etc/runner/config.toml
03

Install the service

The new system service checks Docker and GitHub access before starting.

sudo /usr/local/bin/runner service install --config-path /etc/runner/config.toml
sudo /usr/local/bin/runner status
01

Prepare the Mac

Install Tart and pull a compatible VM image, then install the runner binary from a local GUI session.

curl -fsSL https://raw.githubusercontent.com/ysya/runscaler/main/install.sh | sh -s -- --user
02

Save and add credentials

Paste the TOML into the file, fill the PAT locally or place the App key file, then protect the config.

mkdir -p ~/.config/runner
chmod 0700 ~/.config/runner
nano ~/.config/runner/config.toml
chmod 0600 ~/.config/runner/config.toml
03

Validate and install

Run from your macOS login session.

~/.local/bin/runner validate
~/.local/bin/runner service install --scope user
~/.local/bin/runner status
